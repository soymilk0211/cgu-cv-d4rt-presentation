# D4RT 簡化版｜助教可能會問的題目

先講結論，一兩句就好。被追問再補細節。論文沒寫的地方，就直接說「論文正文沒寫」。

## 1. 沒有相機輸出頭，相機參數是怎麼來的？

**答：** 用 query 問出來的。外參的做法是，在粗網格上取一批點，對第 i 幀和第 j 幀的相機座標各問一次，同一批點就會有兩組三維位置，再用 Umeyama 演算法（一次 3×3 SVD）算出兩個相機之間的剛體變換。內參的做法是，假設針孔相機、主點在畫面中心 (0.5, 0.5)，從三維點反推焦距：fx = pz(u − 0.5)/px，再對多個估計取中位數。（Table 1、第 2.1 節）

## 2. 為什麼這麼快？

**答：** 有三個原因。編碼器只跑一次。解碼器很輕，只有 1.44 億參數。每個 query 獨立，只算你問的點，還可以平行算。要追蹤所有像素的話，論文的 Algorithm 1 會跳過已經被軌跡經過的像素，依運動複雜度大約能加速 5 到 15 倍。（Figure 3：姿勢估計在單張 A100 上超過 200 FPS）

## 3. query 之間為什麼不互相做 self-attention？這樣不是比較準嗎？

**答：** 論文試過，讓 query 互相看不但比較貴，還會過度擬合訓練時的 query 分布，測試時表現會大幅下降。所以他們刻意讓每個 query 獨立解碼，讓一致性由編碼器寫進 F 裡。（第 2.2 節 Pointwise decoder 段，論文說是早期實驗觀察到的）

## 4. 物體被擋住怎麼辦？

**答：** 論文寫到兩點。第一，模型會另外預測這個點在目標時間看不看得到（可見性，訓練時有對應的損失）。第二，它可以從任何一幀的像素出發，不像 SpatialTrackerV2 只能從一幀開始，所以第一幀被擋住的地方，D4RT 的重建不會留洞（Figure 4）。我們自己的理解是：因為 query 的目標時間可以跟來源時間不同，被擋住的時刻也可以問位置；但準不準，論文沒有單獨評估，台上要說這是我們的推論。如果整段影片都沒拍到，就根本問不到，這是我們在限制那頁講的。

## 5. 它在每個 benchmark 都是第一嗎？

**答：** 不是。整體是最先進，但有幾格別人比較好：ScanNet 的 RPE-R，π³ 0.291 比 D4RT 0.302 好（Table 6）；Bonn 的深度 π³ 比較好（Table 5）；追蹤的 ADT 子集，在沒給真實內參時，SpatialTrackerV2 比較好（Table 4）。

## 備用題

**Q：一定要給相機內參嗎？**  
不用，輸入只要一段單鏡頭影片。Table 4 也比較了「有給」和「沒給」真實內參兩種情況。

**Q：9×9 的局部影像塊有什麼用？**  
它讓 query 對位更準，也幫忙切出物體邊界。Table 7（ViT-L、Sintel）裡，加上之後深度 AbsRel（只對齊尺度）從 0.366 降到 0.302，相機 ATE 從 0.173 降到 0.091。Figure 6 的深度圖邊緣明顯比較清楚。

**Q：可以自己跑或重現嗎？**  
我們在論文和專案頁都沒看到官方程式碼或模型（2026/11/17 查的），訓練還用了內部資料。作者說只用公開資料訓練的版本仍然是最先進，但那組數字在附錄，正文看不到，所以我們不引用數字。

**Q：編碼器多大？怎麼初始化？**  
ViT-g，40 層，大約 10 億參數，用公開的 VideoMAEv2 權重初始化。論文說這一步很關鍵，換成隨機初始化會明顯變差，細節在附錄。
